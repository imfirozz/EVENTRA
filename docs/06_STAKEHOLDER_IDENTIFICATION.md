## 1. Stakeholder Analysis Table

| Stakeholder | Role | Primary Interest | Responsibilities | Interaction with System | Important Concerns | Security / Privacy Considerations |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Customer (Attendee)** | End User / Ticket Buyer | Discovering tech events, purchasing valid tickets, fast venue entry. | Provide valid booking details, make payment, present QR pass at venue. | Browses catalog, reserves hold, completes checkout, views/downloads QR passes. | Phantom inventory, hidden checkout fees, lost passes, site crashes. | PCI-DSS compliant payment processing, PII protection (email, phone), encrypted QR tokens. |
| **Event Organizer** | Event Host & Inventory Owner | Maximizing ticket sales, zero overbooking, tracking revenue analytics. | Create event listings, define ticket tiers/prices, manage inventory stock. | Uses Organizer Dashboard to set up events, view sales metrics, export guest lists. | Overselling capacity, system downtime during flash sales, ticket counterfeiting. | Role-Based Access Control (RBAC), secure payout settings, session token security. |
| **Event Staff (Gate Inspector)** | Venue Operations / Door Check-in | Sub-second ticket scanning and fast crowd movement at entry. | Scan attendee QR passes, verify valid status, allow/deny entry. | Mobile Web Scanner App (camera-based validation) or offline PWA mode. | Scanner lag, network drops at gate, duplicate or shared QR pass attempts. | HMAC-SHA256 signature verification, offline cryptographic key caching, replay attack prevention. |
| **Platform Administrator** | System Moderator / Super Admin | Maintaining platform health, user safety, and operational compliance. | Oversee platform metrics, moderate reported events, suspend fraudulent accounts. | Super-Admin Console for user/organizer moderation, system logs, audit trails. | Malicious event listings, platform abuse, system outages, data corruption. | Multi-Factor Authentication (MFA), strict audit logging of admin actions, principle of least privilege. |
| **Payment Provider (e.g. Stripe)** | Financial Gateway | Secure, compliant card processing and webhook event delivery. | Authorize payments, process charges, trigger webhook callbacks. | Asynchronous HTTP Webhook notifications (`charge.succeeded`, `payment_intent.failed`). | Webhook delivery failure, duplicate webhooks, chargebacks/fraudulent transactions. | Webhook cryptographic signature verification (`Stripe-Signature`), TLS 1.3 encryption, zero PCI data stored locally. |
| **Notification Provider (e.g. SMTP / SendGrid)** | Transactional Messaging Gateway | Reliable delivery of booking confirmation emails and ticket receipts. | Receive email dispatch payloads, deliver emails to recipient inboxes. | REST API / SMTP protocol via asynchronous BullMQ background queue. | Email delivery delays, spam folder categorization, rate limiting. | TLS transport encryption, DKIM/SPF alignment, avoidance of sensitive data in plain-text emails. |
| **Developer / Engineering (Solo Developer)** | Platform Architect & Maintainer | Maintaining clean architecture, test coverage, and low operational complexity. | Author code, maintain ADRs, configure CI/CD, write automated unit/integration tests. | Git repo, IDE, local Docker environment, CI/CD pipeline, monitoring dashboards. | Scope creep, code debt, brittle test suites, unhandled edge cases under load. | Secure coding practices (OWASP Top 10), dependency vulnerability scanning, zero hardcoded secrets. |
| **Infrastructure / Cloud Provider (AWS / VPS / Docker)** | Hosting & Compute Provider | Stable runtime environment, container orchestration, and uptime. | Provide compute, storage, networking, database hosting (PostgreSQL, Redis). | Docker Compose / Container runtime, environment variables, SSL certificates. | Server downtime, memory exhaustion, database disk storage limits. | TLS termination, firewall / security group restriction (PostgreSQL/Redis not exposed publicly), OS security patches. |
| **Support / Operations** | User Assistance & Issue Resolution | Resolving attendee booking queries and organizer ticket disputes. | Assist users with lost tickets, process refunds (via organizer request), investigate failed check-ins. | Support admin tool, audit query logs, booking transaction lookup. | Ambiguous booking states (`RESERVED` vs `PAID`), refund disputes, customer dissatisfaction. | Data minimization when inspecting user bookings, read-only audit log access. |
